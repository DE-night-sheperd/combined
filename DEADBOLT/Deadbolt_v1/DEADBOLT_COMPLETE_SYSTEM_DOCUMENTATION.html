1. SYSTEM OVERVIEW

Deadbolt Endpoint Shield is a comprehensive file access control and data loss prevention system designed to protect sensitive files and folders from unauthorized access, modification, deletion, and exfiltration.

Core Capabilities:

  • Rule-based file/folder access control
  • Token-based authentication for restricted operations
  • Real-time file system monitoring
  • 🧠 AI Neural Web for behavioral analysis and anomaly detection
  • Kernel-mode and user-mode enforcement layers
  • Windows file attribute protection

4. SECURITY MEASURES WITHIN DEADBOLT

🔐 Authentication & Access Control

  • Level 1 Token Key - Password-based authentication for restricted operations
  • Password Complexity - Enforces 8+ chars, uppercase, lowercase, digit
  • DPAPI Encryption - Token encrypted using Windows Data Protection API
  • Rule-Based Access - Granular rules for files/folders

👁️ Monitoring & Detection

  • Real-time Monitoring - Watchdog-based file system event monitoring
  • 🧠 AI Behavioral Analysis - Learns normal behavior, detects anomalies
  • Suspicious Pattern Detection - Flags USB access, mass delete, encryption
  • Risk Scoring - 0.0-1.0 risk score for each operation

💾 Data Protection

  • File Attribute Protection - Sets read-only and hidden attributes
  • Persistent Rule Storage - Rules saved to ~/.deadbolt/
  • HMAC Integrity - Infrastructure for HMAC signing
  • File Hashing - SHA-256 hashing for integrity verification

⚙️ System-Level Protection

  • Kernel-Mode Driver - Windows file system minifilter
  • IRP Filtering - Intercepts I/O Request Packets
  • Dual-Layer Enforcement - Kernel + user-mode protection
  • Secure Config Directory - Best-effort NTFS permission setting

5. HOW END USER IS PROTECTED

🛡️ Protection Mechanisms for the End User

  1. Unauthorized Access Prevention
    • Blocks access to protected files/folders
    • Token required for restricted operations
    • Popup dialog for every sensitive operation
  2. Data Loss Prevention (DLP)
    • Detects and blocks mass file deletion
    • Flags USB/external drive access
    • Monitors for encryption/compression operations
  3. Real-Time Alerts
    • Popup notification on every restricted operation
    • Clear operation details displayed
    • User can Allow or Deny each request
  4. AI-Powered Anomaly Detection
    • Learns normal user behavior patterns
    • Flags deviations from baseline
    • Risk-based authentication requirements

6. HOW OUR SYSTEM PROTECTS ITSELF

  1. Secure Token Storage

7. IDENTIFIED VULNERABILITIES

🔴 CRITICAL VULNERABILITIES

VULN-001: Kernel Driver - Missing Input Validation

Severity: CRITICAL

Description: Kernel-mode driver does not validate IOCTL input buffer sizes or contents

Impact: Buffer overflow, privilege escalation, system crash (BSOD)

Mitigation: Validate all input sizes, use safe memory copy functions

VULN-002: Kernel Driver - NULL Pointer Dereferences

Severity: CRITICAL

Description: Missing NULL checks for UNICODE_STRING Buffer and other pointers

Impact: Instant system crash (Blue Screen of Death)

Mitigation: Add NULL checks for all pointers before dereferencing

🟠 HIGH SEVERITY VULNERABILITIES

VULN-003: Kernel Driver - No Control Device Access Control

Severity: HIGH

Description: Any user can send IOCTLs to \\.\DeadboltMinifilter

Impact: Non-privileged users can add/remove rules

Mitigation: Set proper DACL, restrict to Administrators only

VULN-004: No Anti-Tampering / Process Protection

Severity: HIGH

Description: No protection against user-mode process termination

Impact: Attackers can simply kill the monitor process

Mitigation: Run as Windows Service, implement process protection

🟡 MEDIUM SEVERITY VULNERABILITIES

VULN-005: Plaintext Storage (Fallback)

Severity: MEDIUM

Description: If DPAPI unavailable, token stored in plaintext

Impact: Local attackers can read the token

Mitigation: Always require DPAPI, or use alternative encryption

VULN-006: No Log Integrity

Severity: MEDIUM

Description: Logs stored without integrity checks

Impact: Attackers can modify/delete logs

Mitigation: Sign logs with HMAC, store remotely
